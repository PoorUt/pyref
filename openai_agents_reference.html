Agent
The core building block — defines behavior, tools, and routing
Agent(name, instructions) → tools + handoffs → Runner.run(agent, input) → RunResult.final_output
Agent
(name, instructions=None, model=None, model_settings=None, tools=[], handoffs=[], output_type=None, hooks=None, input_guardrails=[], output_guardrails=[], handoff_description=None)
The primary primitive. instructions is the system prompt — pass a string or a callable (ctx, agent) → str for dynamic prompts. output_type is a Pydantic model class for structured output. handoff_description describes this agent when it appears as a handoff target.
classdataclasscore
agent.name
→ str
Unique identifier. Used in tracing, logs, and as the handoff tool name.
agent.instructions
→ str | Callable[[RunContextWrapper, Agent], str]
System prompt. When callable, receives live context on every turn — use for dynamic, context-aware instructions.
agent.model
→ str | Model | None
Model to use. Accepts a string ("gpt-4o") or a Model instance. Falls back to RunConfig.model if None.
agent.tools
→ list[Tool]
List of tools the agent can call. Can mix function_tool, hosted tools, and agent.as_tool().
agent.handoffs
→ list[Agent | Handoff]
Agents this agent can delegate to. Pass Agent objects directly or wrap with handoff() for customisation.
agent.output_type
→ type[BaseModel] | None
Pydantic model for structured output. When set, the final output is validated and typed. None = plain string output.
structured output
agent.input_guardrails
→ list[InputGuardrail]
Guardrails that screen the user input before the agent processes it. Tripwire raises InputGuardrailTripwireTriggered.
agent.output_guardrails
→ list[OutputGuardrail]
Guardrails that screen the final output before it is returned. Tripwire raises OutputGuardrailTripwireTriggered.
agent.as_tool
(tool_name=None, tool_description=None, custom_output_extractor=None) → FunctionTool
Exposes this agent as a callable tool for another agent. The parent agent calls it like any other tool; the child agent runs to completion and its output is returned as a tool result.
agent-as-tool
agent.clone
(**kwargs) → Agent
Returns a shallow copy of the agent with overridden fields. Useful for creating variants without mutation.
agent.get_system_prompt
(context: RunContextWrapper) → str | None
Resolves instructions — calls it if callable, returns it if string. Called automatically by the runner each turn.

Runner
Executes the agentic loop — manages turns, tool calls, and handoffs
Entry Points
Runner.run
(starting_agent, input, context=None, max_turns=10, hooks=None, run_config=None, previous_response_id=None) → RunResult
Async. Runs the agent loop until a final output is produced or max_turns is exceeded. input can be a plain string or a list of OpenAI message dicts. context is your custom state object. Returns RunResult.
asyncmain entrypoint
Runner.run_sync
(starting_agent, input, context=None, max_turns=10, hooks=None, run_config=None, previous_response_id=None) → RunResult
Synchronous wrapper around Runner.run(). Identical parameters. Use when you are not inside an async context.
sync
Runner.run_streamed
(starting_agent, input, context=None, max_turns=10, hooks=None, run_config=None, previous_response_id=None) → StreamedRunResult
Async. Returns a StreamedRunResult immediately. Iterate with async for event in result.stream_events(): to receive token-by-token output and agent events.
asyncstreaming
RunConfig — global run settings
RunConfig
(model=None, model_provider=None, model_settings=None, handoff_input_filter=None, input_guardrails=[], output_guardrails=[], tracing_disabled=False, trace_include_sensitive_data=True, workflow_name='Agent workflow', trace_id=None, group_id=None)
Run-level configuration passed to Runner.run(). model / model_settings override agent-level settings. handoff_input_filter is a global filter applied to all handoffs. tracing_disabled suppresses all trace output.
dataclass
RunConfig.model
→ str | Model | None
Overrides every agent's model for the entire run. Useful for global model switching in tests.
RunConfig.model_settings
→ ModelSettings | None
Overrides temperature, max_tokens, and other generation params for all agents in the run.
RunConfig.handoff_input_filter
→ HandoffInputFilter | None
Applied to every handoff's input. Lets you strip or transform message history globally (e.g. redact PII before handoff).
RunConfig.trace_include_sensitive_data
→ bool (default True)
When False, LLM inputs/outputs are omitted from traces. Use in production to avoid logging user data.

Tools
Function tools, hosted tools, and the tool base class
Function Tools — turning Python functions into tools
@function_tool
(func=None, *, name_override=None, description_override=None, docstring_style=None, use_docstring_info=True, strict_mode=True, failure_error_function=None)
Decorator that converts a Python function into a FunctionTool. The function signature becomes the JSON schema. Type hints and the docstring (use_docstring_info=True) are used to generate the tool description and parameter descriptions automatically. The first parameter can be RunContextWrapper[T] to receive live context — it is excluded from the schema.
decoratormost common
FunctionTool
(name, description, params_json_schema, on_invoke_tool, strict_json_schema=True, failure_error_function=None)
Raw tool class. on_invoke_tool(ctx, args_json_str) → str | Awaitable[str]. Use when you need to construct the schema manually or wrap a dynamic callable.
classadvanced
FunctionTool.name
→ str
The tool name shown to the model. Defaults to the function name. Override with name_override.
FunctionTool.description
→ str
Shown to the model. Defaults to the function docstring's first paragraph.
FunctionTool.params_json_schema
→ dict
JSON Schema for the tool's parameters, derived from the function signature.
FunctionTool.strict_json_schema
→ bool (default True)
Enforces strict JSON schema validation. Disable only if using union types or other schema features OpenAI strict mode doesn't support.
Hosted Tools — run server-side, no code needed
WebSearchTool
(user_location=None, search_context_size='medium')
Gives the agent live web search via the Responses API. user_location is a WebSearchLocation dict for geo-targeted results. search_context_size: "low" | "medium" | "high".
hostedno code
FileSearchTool
(vector_store_ids, max_num_results=None, include_search_results=False, ranking_options=None, filters=None)
Searches files in OpenAI Vector Stores. vector_store_ids is a list of store IDs. include_search_results=True adds raw chunks to the context.
hostedrag
CodeInterpreterTool
(tool_config=None)
Runs Python in a sandboxed OpenAI environment. Can produce files and images. Use tool_config to pass a CodeInterpreterToolConfig with container settings.
hostedcode execution
ComputerTool
(computer, screenshot_scale_factor=1.0)
Gives the agent computer-use capabilities. computer must implement the Computer protocol (screenshot, click, type, scroll…). Used for CUA (Computer Use Agent) workflows.
hostedcomputer use
HostedMCPTool
(tool_config)
Connects to a remote MCP (Model Context Protocol) server hosted by OpenAI. tool_config specifies the server URL and auth. Tools are discovered and called server-side.
hostedmcp
Tool Base Class & Protocol
Tool
(abstract base — union of all tool types)
Not instantiated directly. Any object in agent.tools must be a FunctionTool, a hosted tool, or an object implementing the tool protocol.
type alias
default_tool_error_function
(ctx, error) → str
Default error handler for tool exceptions. Returns a formatted error string to the model. Override per-tool with failure_error_function.

Handoffs
Delegate control from one agent to another
Agent A produces output → model calls transfer_to_agent_b → on_handoff callback → Agent B continues the run
handoff
(agent, on_handoff=None, tool_name_override=None, tool_description_override=None, input_type=None, input_filter=None) → Handoff
Customises how an agent appears as a handoff target. on_handoff(ctx, input?) → None is called when the handoff is triggered — use it to log, mutate context, or validate. input_type is a Pydantic model: if set, the model must pass structured data when handing off. input_filter transforms the message history before the target agent sees it.
factory
Handoff
.agent · .tool_name · .tool_description · .input_json_schema · .on_invoke_handoff · .input_filter
Object returned by handoff(). Passed directly into agent.handoffs. When the model calls the handoff tool, control transfers to .agent.
class
Handoff.tool_name
→ str
The tool name the model sees — defaults to transfer_to_{agent.name} (lowercased, spaces → underscores). Override with tool_name_override.
Handoff.input_filter
→ HandoffInputFilter | None
Called with HandoffInputData before the target agent receives the history. Use to remove, redact, or summarise prior messages.
HandoffInputData
.input_history · .pre_handoff_items · .new_items
Passed to input_filter. input_history = original user input, pre_handoff_items = items before handoff, new_items = items from the handing-off agent's turn.
dataclass
HandoffInputFilter
(HandoffInputData) → HandoffInputData
Callable type alias. Return a modified HandoffInputData to control exactly what history the next agent sees.
type alias
handoff_filters.remove_all_tools
(data: HandoffInputData) → HandoffInputData
Built-in filter: strips all tool call and tool result items from the history before handoff. Keeps only user/assistant text messages.
built-in filter
handoff_filters.keep_last_n_items
(n: int) → HandoffInputFilter
Factory that returns a filter keeping only the last n run items (not counting original input). Trims long histories before handoff.
built-in filter

Context
Pass and share state across agents, tools, and hooks within a single run
RunContextWrapper[TContext]
.context · .usage · .model_name_hint
Wrapper around your custom context object, passed as the first argument to tools (when typed), hooks, dynamic instructions, and guardrails. Access your state via .context. TContext is your user-defined type (any Python object — dataclass, Pydantic model, plain dict). The same RunContextWrapper instance is shared across all agents and tools within one run.
classgeneric
wrapper.context
→ TContext
Your custom state object. Mutable — modifications made in tools or hooks are visible everywhere in the same run.
wrapper.usage
→ Usage
Tracks token usage accumulated so far in the run. .input_tokens, .output_tokens, .total_tokens.
Context in tools — pattern
def my_tool(ctx: RunContextWrapper[MyCtx], arg: str) → str
Declare the first parameter as RunContextWrapper[T]. The SDK injects the context automatically; the parameter is excluded from the JSON schema sent to the model.
pattern
Context in instructions — pattern
instructions=lambda ctx, agent: f"User is {ctx.context.username}"
Pass a callable to Agent.instructions. It receives RunContextWrapper and the current Agent. Evaluated fresh every turn.
pattern
Usage
.input_tokens · .output_tokens · .total_tokens
Token consumption for the entire run. Accessed via RunContextWrapper.usage during the run, or RunResult.input_guardrail_results / output_guardrail_results after.
dataclass

Guardrails
Screen inputs and outputs — run in parallel with the agent
User input arrives → InputGuardrail runs (parallel) → Agent runs → OutputGuardrail runs (parallel) → Result returned
@input_guardrail
(func) → InputGuardrail
Decorator. The decorated async function receives (ctx: RunContextWrapper, agent: Agent, input: str | list) and must return GuardrailFunctionOutput. When tripwire_triggered=True, the run is aborted immediately and InputGuardrailTripwireTriggered is raised. Input guardrails run in parallel with the first agent turn.
decorator
@output_guardrail
(func) → OutputGuardrail
Decorator. The decorated async function receives (ctx: RunContextWrapper, agent: Agent, output: T) where T is the agent's output type. Must return GuardrailFunctionOutput. When tripped, raises OutputGuardrailTripwireTriggered. Output guardrails run only on the final agent's output.
decorator
GuardrailFunctionOutput
(tripwire_triggered: bool, output_info: Any = None)
Returned by every guardrail function. tripwire_triggered=True halts the run. output_info can hold any debug data — accessible on the raised exception.
dataclass
InputGuardrail
(guardrail_function, name=None)
Class returned by the @input_guardrail decorator. Can also be constructed directly. name appears in traces.
class
OutputGuardrail
(guardrail_function, name=None)
Class returned by the @output_guardrail decorator.
class
InputGuardrailResult
.guardrail · .output
Stored in RunResult.input_guardrail_results. .output is the GuardrailFunctionOutput from the guardrail.
dataclass
OutputGuardrailResult
.guardrail · .agent · .agent_output · .output
Stored in RunResult.output_guardrail_results. Includes which agent produced the output and what the guardrail returned.
dataclass

Streaming
Token-by-token output and real-time agent events
StreamedRunResult
.stream_events() · .final_output · .current_agent · .is_complete · .new_items · .last_agent
Returned by Runner.run_streamed(). Use async for event in result.stream_events() to receive events. After the generator exhausts, .final_output and .new_items are populated. Always consume the stream fully before accessing final results.
class
stream_result.stream_events
() → AsyncIterator[StreamEvent]
Async generator yielding all stream events. Exhausting this generator is what drives the run — do not call final_output before iterating fully.
async generator
stream_result.final_output
→ T (populated after stream completes)
The typed final output, same as RunResult.final_output. Available only after the stream is fully consumed.
stream_result.current_agent
→ Agent (updates live)
The currently-executing agent. Changes when a handoff occurs. Read after AgentUpdatedStreamEvent to get the new agent.
Stream Event Types
RawResponsesStreamEvent
.data → ResponseStreamEvent .type = "raw_response_event"
Passes through the raw OpenAI Responses API streaming event. Contains token deltas, tool call deltas, etc. Use when you need maximum control.
low-level
RunItemStreamEvent
.item → RunItem .name → str .type = "run_item_stream_event"
Emitted when a complete RunItem is produced (message, tool call, tool output, handoff). Higher-level than raw events — use for chat UIs.
high-level
AgentUpdatedStreamEvent
.new_agent → Agent .type = "agent_updated_stream_event"
Emitted when the run switches to a new agent via handoff. .new_agent is the incoming agent.
StreamEvent.type values
"raw_response_event" | "run_item_stream_event" | "agent_updated_stream_event"
Discriminator field on every event. Use isinstance() checks or match on .type to route handling logic.

Hooks
Lifecycle callbacks — observe and act on every step of the agentic loop
RunHooks — attached to a single run via Runner.run(hooks=...)
RunHooks[TContext]
class RunHooks(Generic[TContext]):
Subclass and override any combination of async methods. A single instance is shared across all agents in the run. All methods receive context: RunContextWrapper[TContext] as the first argument.
base class
RunHooks.on_agent_start
(context, agent) → None
Called before an agent begins its turn. Also fires on the initial agent and after each handoff.
RunHooks.on_agent_end
(context, agent, output) → None
Called when an agent produces a final output (not when it hands off). output is the typed result.
RunHooks.on_tool_start
(context, agent, tool) → None
Called before a tool is invoked. tool is the FunctionTool or hosted tool object.
RunHooks.on_tool_end
(context, agent, tool, result) → None
Called after a tool returns. result is the string returned by the tool.
RunHooks.on_handoff
(context, from_agent, to_agent) → None
Called when a handoff is triggered. Both source and target agents are provided.
AgentHooks — attached to a specific agent via Agent(hooks=...)
AgentHooks[TContext]
class AgentHooks(Generic[TContext]):
Same interface as RunHooks but fires only for the agent it is attached to. Use for per-agent observability (e.g. logging a specialist agent's tool calls separately).
base class
AgentHooks.on_start
(context, agent) → None
Called before this agent's turn begins.
AgentHooks.on_end
(context, agent, output) → None
Called when this agent produces its final output.
AgentHooks.on_tool_start / on_tool_end
(context, agent, tool) / (context, agent, tool, result)
Called before/after each tool invocation for this agent.
AgentHooks.on_handoff
(context, agent, source) → None
Called on the receiving agent when it is handed off to. source is the handing-off agent.

Tracing
Built-in observability — view on OpenAI dashboard or export to custom backends
trace
(workflow_name, trace_id=None, group_id=None, disabled=False, metadata=None) → context manager
Creates a top-level trace span. Use with trace("my workflow"): to wrap a multi-run workflow so all runs share the same trace ID on the dashboard. group_id groups multiple traces into one conversation thread.
context manager
custom_span
(name, data=None) → context manager
Creates a custom child span inside an existing trace. Use to instrument non-agent code (database calls, pre-processing) within the same trace tree.
context manager
agent_span
(name, handoffs=None, tools=None, output_type=None) → context manager
Creates an agent-type span. Emitted automatically by the runner — use manually only in custom integrations.
function_span
(name, input=None, output=None) → context manager
Creates a function/tool-type span. Emitted automatically for tool calls.
generation_span
(model=None, model_config=None, input=None, output=None, usage=None) → context manager
Wraps an LLM call. Automatically created by model providers — use manually when integrating a custom model.
guardrail_span
(name, triggered=None) → context manager
Wraps a guardrail check. Auto-created for registered guardrails.
add_trace_processor
(processor: TracingProcessor) → None
Registers an additional processor alongside the default OpenAI exporter. Use to stream spans to Datadog, Langfuse, custom loggers, etc.
set_trace_processors
(processors: list[TracingProcessor]) → None
Replaces the entire processor list. Pass [] to disable all tracing output.
set_tracing_disabled
(disabled: bool) → None
Globally toggles tracing on or off. Equivalent to setting RunConfig.tracing_disabled on every run.
set_tracing_export_api_key
(api_key: str) → None
Overrides the API key used to export traces. Defaults to OPENAI_API_KEY.
TracingProcessor
on_trace_start(trace) / on_trace_end(trace) / on_span_start(span) / on_span_end(span) / shutdown() / force_flush()
Abstract base class for custom trace exporters. Override any combination of methods. Register with add_trace_processor().
abstract class

Models & Settings
Configure which model runs and how
ModelSettings — generation parameters
ModelSettings
(temperature=None, top_p=None, frequency_penalty=None, presence_penalty=None, tool_choice=None, parallel_tool_calls=None, truncation=None, max_tokens=None, reasoning=None, include_usage=None, extra_query=None, extra_body=None, extra_headers=None)
Dataclass for LLM sampling parameters. None fields use the model default. Pass to Agent(model_settings=...) or RunConfig(model_settings=...). Run-level settings override agent-level.
dataclass
ModelSettings.tool_choice
→ "auto" | "required" | "none" | str
"auto" (default) lets the model decide. "required" forces a tool call every turn. "none" prevents tool calls. Pass a tool name string to force a specific tool.
ModelSettings.parallel_tool_calls
→ bool | None
When True, the model may call multiple tools in one turn. When False, tool calls are serial.
ModelSettings.truncation
→ "auto" | "disabled" | None
Context truncation strategy for the Responses API. "auto" drops oldest messages when context exceeds the model's limit.
ModelSettings.reasoning
→ Reasoning | None
Controls extended reasoning for o1/o3/o4-mini models. Reasoning(effort="medium") — effort: "low" | "medium" | "high".
o-series

Uses the Responses API (/v1/responses). Default when passing a model string to an agent. Supports stateful conversation, built-in tools, and streaming natively.
default
OpenAIChatCompletionsModel
(model: str, openai_client: AsyncOpenAI)
Uses the standard Chat Completions API (/v1/chat/completions). Compatible with OpenAI-compatible third-party providers (Groq, Mistral, Ollama, etc.).
chat completions
Model
get_response() / stream_response() (protocol)
Protocol (interface) that custom model wrappers must implement. Use to integrate any LLM provider.
protocol
ModelProvider

Factory protocol. Implement to swap all model creation in a run via RunConfig(model_provider=...).
protocol
OpenAIProvider
(api_key=None, base_url=None, openai_client=None, use_responses=True)

Global helpers. set_default_openai_client lets you pass a custom AsyncOpenAI instance (e.g. with Azure endpoint). set_default_openai_api switches the default API type globally.

Exceptions
All exceptions raised by the SDK
AgentsException
(base class for all SDK exceptions)
Root exception class. Catch this to handle any SDK error.
base
MaxTurnsExceeded
.max_turns
Raised when the run reaches max_turns without producing a final output. Increase max_turns or redesign the agent to terminate sooner.
InputGuardrailTripwireTriggered
.guardrail_result → InputGuardrailResult
Raised when an input guardrail returns tripwire_triggered=True. Access .guardrail_result.output.output_info for debug data.
OutputGuardrailTripwireTriggered
.guardrail_result → OutputGuardrailResult
Raised when an output guardrail trips. The run completed but output was blocked. Use .guardrail_result.agent_output to inspect what was blocked.
ModelBehaviorError
(message: str)
Raised when the model returns something the SDK cannot parse — e.g. invalid JSON for a structured output, unknown tool name, or malformed handoff. Usually indicates a prompt or schema issue.
UserError
(message: str)
Raised for incorrect SDK usage — e.g. calling a method with invalid arguments, using a non-async function as an async tool, or misconfiguring an agent. Fix the calling code.
